この学習サイト自体が、Cloudflare の各プリミティブを組み合わせて構築されたフルスタックアプリケーションです。教材を読むだけでなく「実際に動いているもの」を題材にできるよう、構成を意図的に Cloudflare スタックで固めています。このレッスンでは全体像を俯瞰します。

## モノレポ構成

リポジトリは pnpm workspace のモノレポで、役割の異なる2つのアプリに分かれています。

- **`apps/web`** — Next.js（App Router）を **OpenNext** で Cloudflare Workers 上にデプロイするフロントエンド兼 BFF。レッスン本文（MDX）の SSG と、Hono による API ルートを担います。
- **`workers/demos`** — 各 Cloudflare サービスの実デモを提供する独立した **Hono Worker**。KV・R2・D1・Durable Objects・Containers のデモ API を集約します。

```text
apps/
  web/        # Next.js + OpenNext (フロント + API)
workers/
  demos/      # Hono Worker (デモ API 群)
```

UI と「本物のサービスを叩くデモ」を別 Worker に分けることで、フロントの SSG/ISR と、状態を持つデモ実行を独立してスケール・デプロイできます。

## OpenNext で Next.js を Workers 上で動かす

Next.js はそのままでは Node.js サーバー前提ですが、**OpenNext の Cloudflare アダプタ**がビルド成果物を Workers ランタイム向けに変換します。これにより、レッスンページは SSG（静的生成）され、エッジから即座に配信されます。

## web ↔ demos を結ぶ Service Binding

`apps/web` から `workers/demos` を呼び出す際は、公開 URL を経由せず **Service Binding** を使います。同一 Cloudflare ネットワーク内で Worker 同士を直接 `fetch` でき、ネットワークの往復やレイテンシ・認証の手間を避けられます。

```ts
// web 側から demos Worker を Service Binding 経由で呼ぶイメージ
const res = await env.DEMOS.fetch(new Request("https://demos/health"));
const data = await res.json();
```

API を別 Worker に分離する狙いは、(1) フロント配信とデモ実行の責務分割、(2) デモ側だけを独立してデプロイ・スケール可能にすること、(3) 状態を持つ Durable Objects / Containers をデモ Worker に閉じ込めることです。

## 各プリミティブの役割

このサイトが扱う Cloudflare スタックと、それぞれの担当領域は次の通りです。

- **Workers** — エッジでの動的実行基盤（すべての土台）
- **OpenNext** — Next.js を Workers 上で動かすアダプタ
- **D1 + Drizzle ORM** — リレーショナル（SQLite）データ。ゲストブック等のデモ
- **R2** — egress 無料のオブジェクトストレージ
- **KV** — 低レイテンシで読める結果整合の Key-Value ストア
- **Durable Objects** — 強整合な状態とインメモリ・ストレージを併せ持つ単位
- **Containers** — Docker イメージをエッジで実行する計算レイヤー
- **Flagship** — フィーチャーフラグ・評価システム
